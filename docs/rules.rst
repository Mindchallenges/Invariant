Layering

.. rule:: Only the CLI imports the oracle
   :id: RULE_LAYERS_ONLY_THE_CLI_IMPORTS_THE_ORACLE
   :decided_by: DEC_ADR_007_D6

   No module under core, domains, adapters or hosts imports anything from the oracle. The arrows into the oracle come from the CLI alone, so the engine works identically whether or not the oracle is ever used, and a host only says what happened while the CLI writes the sidecar.

   - Rule: ``layers.only-the-cli-imports-the-oracle``
   - Severity: blocker
   - Phases: design, review, landing
   - Applies to: ``src/invariant/core/*.py``, ``src/invariant/domains/*.py``, ``src/invariant/adapters/*.py``, ``src/invariant/hosts/*.py``
   - Check: boundary (imports): may not reference ``src/invariant/oracle/*``
   - Rationale: To fix a finding, move the call up into the CLI, which may import the oracle, and hand what the lower layer needs down to it as a value or a callable. docs/architecture/overview.rst draws every arrow into oracle/ from the CLI, and ADR-007 D6 is why there is no hosts-to-oracle arrow.
   - Links: ``docs/architecture/overview.rst``

Agent conduct
-------------

.. rule:: Interview the user when their input is needed
   :id: RULE_CONDUCT_INTERVIEW_WHEN_INPUT_IS_NEEDED

   When a decision is genuinely the user's, and neither the request, the code, the architecture docs, the design system nor a sensible default settles it, interview the user: a focused round of questions with concrete options, repeated until the answer is clear. Do not guess the answer, and do not stop with a vague hand-back in place of the questions. A decision that can be inferred is made and stated, not asked.

   - Rule: ``conduct.interview-when-input-is-needed``
   - Severity: warn
   - Phases: always
   - Applies to: ``CLAUDE.md``, ``.claude/agents/*.md``, ``src/invariant/data/agents/*.md``, ``src/invariant/data/skills/**``
   - Check: judgement: a cited verdict, evidence citation, scope diff; N/A when: asking-unchanged
   - Rationale: To fix a finding, make the agent's instructions name the interview round (an INTERVIEW block, or a multiple-choice question where the host offers one) at the point where it would otherwise guess or bail. The user asked for this on 2026-11-08; the backlog-curator's INTERVIEW relay and feature-architect's STOP reports are the existing shapes.
   - Links: ``.claude/agents/backlog-curator.md``, ``.claude/agents/feature-architect.md``

Design records
--------------

.. rule:: Work items carry no design
   :id: RULE_DOCS_ITEMS_CARRY_NO_DESIGN

   An item holds the problem, the evidence and the status; a ruling or design in it is a decision need linked by id.

   - Rule: ``docs.items-carry-no-design``
   - Severity: warn
   - Phases: review
   - Applies to: ``docs/backlog.rst``
   - Check: judgement: a cited verdict, evidence citation, scope diff
   - Rationale: To fix a finding, write the ruling or the design as a decision need (invariant docs decision new) and leave only its id in the item. items.decisions_linked checks mechanically that every id an item names is a need the build holds; the prose around the ids is this rule's.

.. rule:: Every decision a session made is declared
   :id: RULE_DOCS_DECISIONS_ARE_DECLARED

   A decision a session makes is declared with `invariant session decisions add`, as the id of its need or as a draft that becomes one, before the session lands. A decision written only in an agent report, a plan or a commit message is not recorded.

   - Rule: ``docs.decisions-are-declared``
   - Severity: warn
   - Phases: review
   - Applies to: ``**``
   - Check: judgement: a cited verdict, evidence citation, scope diff
   - Rationale: To fix a finding, declare each undeclared decision (invariant session decisions add) and write it as a need. docs.decisions_recorded holds the declared ones at the landing; a decision nobody declared is visible only to this review.

SOLID principles
----------------

.. rule:: Single responsibility
   :id: RULE_SOLID_SINGLE_RESPONSIBILITY

   Each module, type and function a change adds or edits has one reason to change: it answers to one owner, named in the architecture docs.

   Fix: split the unit along its owners and name each part's owner in the docs; a unit doing two things for two callers is two units.

   - Rule: ``solid.single-responsibility``
   - Severity: blocker
   - Phases: design, review, landing
   - Applies to: ``**/*.py``
   - Check: judgement: a cited verdict, evidence citation, scope diff; N/A when: no_executable_change
   - Owner: user (only the user excepts, loosens or rewords it; an agent proposes)
   - Rationale: It keeps a change isolated to the one owner who asked for it, so a change for one caller cannot break another. The component responsibilities in the architecture overview are where each unit's owner is named.

.. rule:: Open/closed
   :id: RULE_SOLID_OPEN_CLOSED

   New behaviour is added by extension (a new implementation of an existing seam, a new data entry, a new strategy), not by growing a conditional over kinds inside code that already works.

   Fix: where a change adds a branch on a type or kind tag, introduce or reuse the seam and add the new case as its implementation.

   - Rule: ``solid.open-closed``
   - Severity: blocker
   - Phases: design, review, landing
   - Applies to: ``**/*.py``
   - Check: judgement: a cited verdict, evidence citation, scope diff; N/A when: no_executable_change
   - Owner: user (only the user excepts, loosens or rewords it; an agent proposes)
   - Rationale: It leaves working code untouched when a new case arrives, so what was tested stays as it was tested. The seams a component offers are named in its responsibilities in the architecture overview.

.. rule:: Liskov substitution
   :id: RULE_SOLID_LISKOV_SUBSTITUTION

   Every implementation of an interface or subclass honours its contract: it accepts what the base accepts, promises what it promises, and raises nothing the base does not declare. No caller checks which implementation it holds.

   Fix: where an implementation narrows input, weakens output or is type-checked by a caller, change the contract in the docs or stop implementing it.

   - Rule: ``solid.liskov-substitution``
   - Severity: blocker
   - Phases: design, review, landing
   - Applies to: ``**/*.py``
   - Check: judgement: a cited verdict, evidence citation, scope diff; N/A when: no_executable_change
   - Owner: user (only the user excepts, loosens or rewords it; an agent proposes)
   - Rationale: It keeps every seam substitutable, so a caller written against the contract works with any implementation. A contract lives with the component that owns it in the architecture overview.

.. rule:: Interface segregation
   :id: RULE_SOLID_INTERFACE_SEGREGATION

   A client depends only on the operations it uses. An interface a change adds or widens is shaped by its callers, and no implementation is forced to stub operations it cannot honour.

   Fix: split the interface by client role; let each caller depend on its own role.

   - Rule: ``solid.interface-segregation``
   - Severity: blocker
   - Phases: design, review, landing
   - Applies to: ``**/*.py``
   - Check: judgement: a cited verdict, evidence citation, scope diff; N/A when: no_executable_change
   - Owner: user (only the user excepts, loosens or rewords it; an agent proposes)
   - Rationale: It keeps coupling narrow, so a change to one caller's needs does not ripple into callers that never used it. Each client role is named with its component in the architecture overview.

.. rule:: Dependency inversion
   :id: RULE_SOLID_DEPENDENCY_INVERSION

   Policy depends on abstractions it owns; details implement them and are injected at the composition root. No high-level unit constructs or looks up a concrete detail.

   Fix: define the abstraction where the policy lives, implement it outward, and inject it from the entry point. The import-visible half is the derived layer rules'.

   - Rule: ``solid.dependency-inversion``
   - Severity: blocker
   - Phases: design, review, landing
   - Applies to: ``**/*.py``
   - Check: judgement: a cited verdict, evidence citation, scope diff; N/A when: no_executable_change
   - Owner: user (only the user excepts, loosens or rewords it; an agent proposes)
   - Rationale: It keeps policy testable without its details, which arrive through an injected abstraction rather than a constructor call or a lookup. The architecture overview names which component owns each abstraction.
