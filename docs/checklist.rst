Layering

layers.only-the-cli-imports-the-oracle: Only the CLI imports the oracle
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

No module under core, domains, adapters or hosts imports anything from the oracle. The arrows into the oracle come from the CLI alone, so the engine works identically whether or not the oracle is ever used, and a host only says what happened while the CLI writes the sidecar.

- Severity: blocker
- Phases: design, review, landing
- Applies to: ``src/invariant/core/*.py``, ``src/invariant/domains/*.py``, ``src/invariant/adapters/*.py``, ``src/invariant/hosts/*.py``
- Check: boundary (imports): may not reference ``src/invariant/oracle/*``
- Rationale: To fix a finding, move the call up into the CLI, which may import the oracle, and hand what the lower layer needs down to it as a value or a callable. docs/architecture/overview.rst draws every arrow into oracle/ from the CLI, and ADR-007 D6 is why there is no hosts-to-oracle arrow.
- Links: ``docs/architecture/overview.rst``, ``DEC_ADR_007_D6``

layers.oracle-never-imports-hosts: The oracle never imports a host
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

No module under oracle imports anything from hosts. Host facts and effects reach the oracle through a protocol the oracle defines and the CLI injects an implementation of.

- Severity: blocker
- Phases: design, review, landing
- Applies to: ``src/invariant/oracle/*.py``
- Check: boundary (imports): may not reference ``src/invariant/hosts/*``
- Rationale: To fix a finding, define the shape the oracle reads (as HostProbe and HostSeams are), implement it in hosts, and have the CLI inject it. docs/architecture/overview.rst records that no oracle-to-hosts arrow exists, and ADR-007 D11 is the probe the CLI injects.
- Links: ``docs/architecture/overview.rst``, ``DEC_ADR_007_D11``

Agent conduct
-------------

conduct.interview-when-input-is-needed: Interview the user when their input is needed
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

When a decision is genuinely the user's, and neither the request, the code, the architecture docs, the design system nor a sensible default settles it, interview the user: a focused round of questions with concrete options, repeated until the answer is clear. Do not guess the answer, and do not stop with a vague hand-back in place of the questions. A decision that can be inferred is made and stated, not asked.

- Severity: warn
- Phases: always
- Applies to: ``CLAUDE.md``, ``.claude/agents/*.md``, ``src/invariant/data/agents/*.md``, ``src/invariant/data/skills/**``
- Check: judgement: a cited verdict, evidence citation, scope diff; N/A when: asking-unchanged
- Rationale: To fix a finding, make the agent's instructions name the interview round (an INTERVIEW block, or a multiple-choice question where the host offers one) at the point where it would otherwise guess or bail. The user asked for this on 2026-11-08; the backlog-curator's INTERVIEW relay and feature-architect's STOP reports are the existing shapes.
- Links: ``.claude/agents/backlog-curator.md``, ``.claude/agents/feature-architect.md``

Design records
--------------

docs.items-carry-no-design: Work items carry no design
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

An item holds the problem, the evidence and the status; a ruling or design in it is a decision need linked by id.

- Severity: warn
- Phases: review
- Applies to: ``docs/backlog.rst``
- Check: judgement: a cited verdict, evidence citation, scope diff
- Rationale: To fix a finding, write the ruling or the design as a decision need (invariant docs decision new) and leave only its id in the item. items.decisions_linked checks mechanically that every id an item names is a need the build holds; the prose around the ids is this rule's.

docs.decisions-are-declared: Every decision a session made is declared
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

A decision a session makes is declared with `invariant session decisions add`, as the id of its need or as a draft that becomes one, before the session lands. A decision written only in an agent report, a plan or a commit message is not recorded.

- Severity: warn
- Phases: review
- Applies to: ``**``
- Check: judgement: a cited verdict, evidence citation, scope diff
- Rationale: To fix a finding, declare each undeclared decision (invariant session decisions add) and write it as a need. docs.decisions_recorded holds the declared ones at the landing; a decision nobody declared is visible only to this review.
